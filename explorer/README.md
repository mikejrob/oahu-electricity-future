# Interactive results explorer

A serverless Shiny app (compiled to WebAssembly with
[shinylive](https://posit-dev.github.io/r-shinylive/)) that lets readers
browse every solved scenario of the study: system costs, generation mixes,
emissions, and hourly dispatch. Modeled on the
[MIP results explorer](https://gschivley.github.io/MIP-shinylive/).

**Live site:** https://mikejrob.github.io/oahu-electricity-future/

## Pieces

- `app.R` — the app (R Shiny + bslib + ggplot2/plotly).
- `data/*.csv`, `data/meta.json` — compact extracts of the solve fleet,
  generated by `build/build_explorer_data.py` from the working repository
  (the full outputs never leave the cluster). One row per scenario in
  `scenarios.csv`; tidy scenario × period × technology tables behind the
  charts.
- `.github/workflows/deploy-explorer.yml` — on every push touching
  `explorer/`, GitHub Actions exports the app with
  `shinylive::export()` and deploys it to GitHub Pages.

## Refreshing the data

From the working repository root on Koa:

```bash
python3 build/build_explorer_data.py   # rewrites explorer/data/
./push_both.sh "Refresh explorer data"
```

The site rebuilds automatically a few minutes after the push.

## Coverage and conventions

The extracts cover the report-basis fleet only: the report-basis
distributed-solar families (`nlv2b`/`nlv2s`/`nlv2a`) on the four market oil
paths plus the EIA reference. Legacy gross-load families and archived AEO
oil paths are excluded so no chart mixes netting conventions.

Two populations are carried, counted separately in `meta.json`
(`matrix_cells`, `plan_cells`) and in the app header. The **scenario
matrix** is what the model chooses given costs and constraints — 513 cells,
the same set as `results/RESULTS_SUMMARY.csv`. The **published-plan cells**
hold generation to a plan somebody else published (Section 4.5); they are
labelled `Published plan: …` and are not part of the 513. Only the current
quota design is exported — `PLAN_DESIGN` in the extractor gates it, so
superseded designs cannot leak into the site. Approximations
(thermal oil/LNG split, reconstructed netted-distributed series, the
optional conversion-capital charge) are documented in the app's About tab
and in the extractor's docstring.

## Invariants (guarded)

`check_app_invariants.py` runs in `push_both.sh` and blocks a sync if a
known regression reappears: the System-costs chart must keep a fixed
minimum thickness per bar (`BAR_PX`) with the height enforced at both the
container and the plot device, `page_navbar` must stay `fillable = FALSE`
(bslib's fillable pages flex-squeeze tall charts to viewport height), and
no raw config string may leak into `config_label` in the data extract.
